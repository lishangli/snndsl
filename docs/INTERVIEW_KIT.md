# 用户访谈工具包（P0-2）

> 这一项我没法代做。编出来的访谈记录比没有访谈更糟——
> 它会让我们拿着一份自己写的剧本，去确认一个自己想要的结论。
>
> 所以这里给的是**能直接拿去用**的东西：找谁、问什么、怎么记、什么结果算失败。
> 12 场跑完，把表填满，P0 才算真收口。

---

## 1. 找谁：3 类角色 × 4 人

| 角色 | 具体画像 | 从哪找 | 为什么必须有一票 |
|---|---|---|---|
| **硬件厂商工程师** | 在 SynSense / Innatera / BrainChip / 高校 Loihi 组做 SDK、编译器、部署工具 | GitHub issue、厂商论坛、会议 workshop、NIR 仓库 contributor 列表 | 他们决定"我们的输出能不能进他们的工具链"，是**下游守门人** |
| **边缘 AI 产品负责人** | 做 DVS 相机模组、可穿戴、工业检测，手上有一条要低功耗的产线 | 行业展会、LinkedIn、硬件加速器社群 | 他们决定**有没有预算**，也决定痛点排序 |
| **SNN 研究者** | 近两年发过 SNN 训练/部署论文的一作或通讯 | 论文作者邮箱、Twitter/X、实验室主页 | 他们决定**写法会不会被引用**，是 P2 生态信号的来源 |

**配额纪律**：任意一类少于 3 人，结论不成立（会被单一视角带偏）。
凑不齐就明说凑不齐，不要用"从业者"这种模糊身份凑数。

---

## 2. 怎么约：两句话，不要自我介绍超过两行

> 主题：**15 分钟，问几个 SNN 落地时踩过的坑**
>
> 我们在做一个把 SNN 模型直接编译到神经形态硬件的工具，
> 想先搞清楚真实项目里到底卡在哪，不推销、不录屏、不留联系方式。

要点：
- **不要说"我们做了一个 DSL"**。一说，对方就开始评价语法，而我们要问的是流程。
- **给具体时长**（15 分钟），比"方便聊聊吗"的接受率高得多。
- **明确不要 NDAs、不要演示**。降低对方的心理成本。

---

## 3. 问什么：9 个问题

### A. 定位上一次部署（不问假设，只问发生过的事）

1. 你最近一次把 SNN 模型往硬件（或厂商仿真器）上搬，是什么时候？搬的是什么网？
2. **那一次卡在哪一步？** 尽量回忆第一个卡住你的具体报错或现象。
3. 从"训练完"到"硬件上跑出结果"，一共花了多久？其中**调试语义不一致**占多少？

### B. 量化痛点（逼出排序，不要点头）

4. 下面五件事，按你实际花的时间排序：① 训练不收敛 ② 部署后精度掉 ③ 不知道网络装不装得下 ④ 算力/能耗预算估不准 ⑤ 换芯片要重写代码。
5. 如果有一个工具能在**训练完 10 秒内**告诉你"这张网能不能上、差多少、改哪行"，它对你的价值是"省几天"还是"省几小时"？

### C. 现在的替代方案（这决定我们有没有竞争对手）

6. 现在这件事你怎么做？手写映射脚本、还是干脆放弃部署、还是只用厂商给的参考模型？
7. 你有没有因为"部署太麻烦"而**改过网络结构**？改了什么、为什么？

### D. 判定信号（不问喜好，问行为）

8. 上一次你为了一个部署问题去搜/去问人，搜的是什么关键词？（**记录原话**，这是我们的文档标题）
9. 如果这套工具明天开源，你会先拿哪个自己的模型试？（说不出具体模型 = 不是真需求）

> **不要问**："你会用吗""你觉得好用吗""你需要什么功能"。
> 这三类问题拿到的是礼貌，不是信息。

## 4. 怎么记：一人一行，只记原话

| # | 角色 | 项目/规模 | 卡点原话（逐字） | 耗时 | 痛点排序(4) | 替代方案 | 会试的模型(9) | 是否提及部署一致性 |
|---|---|---|---|---|---|---|---|---|
| 1 | | | | | | | | 是/否 |
| … | | | | | | | | |

规则：
- **卡点原话必须逐字**。"精度掉了"没用，"导出来之后第一层就不发放了"有用。
- **痛点排序必须是 1–5 的排列**，不接受"都很重要"。
- **第 9 题答不出具体模型的**，该条记为"弱信号"，不计入分母。

## 5. 什么结果算失败（写在这里，免得事后找理由）

| 观察 | 结论 | 动作 |
|---|---|---|
| 12 人里 **≥4 人**把"部署后精度/语义不一致"排在前三 | 主卖点成立 | 按现路线推 P1 |
| 12 人里 **<4 人**提及部署一致性 | **重新评估定位** | 转向"成本/资源估算"作为主卖点（痛点 #2 同样可验证） |
| **≥7 人**说"我们现在根本不部署，只发论文" | 部署叙事在研究者里不成立 | 研究者这条线只做写法（`.snn` 进附录），产品线只盯硬件厂商与边缘产品 |
| **≥5 人**说"我们只用厂商给的参考模型" | 第三方模型进不去是核心障碍 | 优先做"厂商工具链适配层"，而不是新前端 |

**样本量诚实说明**：12 人是**方向性验证**，不是统计结论。
它的作用是排除明显错误的方向，不是证明"市场有 X 亿"。
任何材料里引用这 12 场访谈，必须写明样本量与角色构成。

## 6. 时间安排（两周内可完成）

| 天 | 动作 |
|---|---|
| D1–D2 | 每个角色列 8 个候选，发 24 封邀请（预期 50% 回复、30% 成行） |
| D3–D7 | 每天 2 场，当天整理原话（不过夜，过夜就只剩印象） |
| D8 | 补齐缺口角色（哪类少于 3 人补哪类） |
| D9–D10 | 填表、按第 5 节判定、写成一页结论 + 原始记录附录 |

## 7. 做完之后要产出什么

1. **一页结论**：主卖点是否成立、痛点排序、最强的三句原话（可直接进投资人材料）
2. **原始记录附录**：12 行表格，不改写、不美化
3. **一句修正**：我们原来的哪句话被证伪了

第 3 条最重要。如果 12 场访谈下来没有任何一句话需要修正，
说明问法有问题，不是方向对。
