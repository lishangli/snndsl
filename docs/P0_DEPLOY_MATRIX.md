# P0 后半段：从"能导出"到"别人能接手"

> 这份文档记录 P0 四个交付物里剩下两个的完成情况（`deploy --report`、多网络部署检查），
> 以及过程中撞到的**上游生态问题**。
> 上游问题比我们自己的结论更重要：它决定了产品叙事该怎么说。

---

## 1. 五个网络，五种结论（P0-4）

`snndsl deploy` 分别跑在仓库自带的五个网络上。没有一个结论是"大概率能跑"，
每条都是可复现的命令行输出。

| 网络 | 结构 | 结论 | 阻断 | 警告 | 实测数值（真实权重，2048 张） |
|---|---|---|---|---|---|
| `mnist_hw.snn` | 784→256→10，zero reset | **可部署** | 0 | 0 | max\|Δ\|=0.0，top-1=100%，第三方复现 100% |
| `mnist_mlp.snn` | 同结构，**subtract** reset | 可部署，会走样 | 0 | 2 | 精度 95.70%→95.61%，top-1 一致率 **99.17%**，单神经元脉冲计数最大偏差 4/8 步 |
| `adaptive_lif.snn` | ALIF（自适应阈值） | **不可部署** | 2 | 1 | 精度 94.53%→**35.40%**，top-1 一致率 **36.38%** |
| `residual_snn.snn` | 残差加法合并 | **不可部署** | 1 | 4 | 导不出：NIR 无 merge 原语 |
| `cifar_hw.snn` | conv→neuron→conv | **不可部署** | 3 | 0 | NIR 1.0.8 神经元层是 1-D，无 Reshape 还原 `(C,H,W)` |

> **一处更正**：本文档早前版本写的 "subtract 78.1%" 与 "ALIF 9.4%"，
> 是在**没有 `--weights` 的情况下测的**——那时 `deploy` 用的是随机初始化网络，
> 两个数字都不携带信息。现已全部用训练好的检查点重测（`build/mnist_mlp.pt`、
> `build_alif/adaptive_lif.pt`）。教训：验证脚本必须自己检查"被验的对象是不是训练过的"，
> 否则它会稳定地输出一个数字，而那个数字什么也不是。

三条结论值得单独说：

**（1）ALIF 从"警告"改成了"阻断"，而且实测支持这个改动。**
原来的实现把它标成 WARN（"导成泄漏积分器，会丢阈值/复位"）。训练出真实权重后跑数值验证：
精度 94.53% → **35.40%**，top-1 一致率 **36.38%**。这不是"近似"，是换了一个模型：
自适应阈值那一项被丢掉了，触发条件整体位移。

> 教训：**严重级别不能靠分类学拍脑袋，得靠实测。**
> 静态规则写下"警告"两个字很便宜，跑一次验证就知道那是灾难。

**（2）subtract reset 的偏差是"可接受但不为零"，不是"崩"。**
真实权重下 top-1 一致率 **99.17%**，精度只掉 0.09pp，但单神经元脉冲计数最多差 4 个
（8 步窗口内）。原因是 NIR 只有固定 `v_reset`，表达不了 `v ← v - v_th`：导成 zero reset
会丢掉超阈值的那部分电位。改法只有一行（`v = v * (1 - s)`），`deploy` 直接把这一行写进建议里。
**"近似"和"等价"必须分开说**——这个案例正好落在两者之间，报告里就写"会走样"。

**（3）残差网和卷积网不是"没做完"，是"标准里没有"。**
- 残差：NIR 没有加法/合并原语，分支无法在标准内汇合。
- 卷积：NIR 神经元层的参数是逐神经元一维数组，`conv → neuron → conv` 需要
  `Reshape` 把 `(C,H,W)` 压平再还原，而 NIR 1.0.8 只有 `Flatten`，没有反向操作。

这两条决定了产品边界：**先做全连接 SNN 的无损部署**，卷积走"向 NIR 提多维神经元扩展"这条路。

## 2. `deploy --report`：一份能直接发给别人的文件（P0-3）

```bash
snndsl deploy examples/mnist_hw.snn --weights build_hw/mnist_hw.pt \
        --data mnist --batch 32 --report deploy_report.html
```

产出是**单文件 HTML**：无 CDN、无外链字体、无 `<script>`、图表是内联 SVG。
理由很实际——这类文件会被邮件转发、在权限受限的笔记本上打开、附在采购工单里。
需要联网才能渲染的报告，恰好在最需要它的时候是白屏。

报告结构（按"读者会先问什么"排序，不按我们做了什么排序）：

| 节 | 回答的问题 |
|---|---|
| 结论横幅 | 能上还是不能上，一句话，带阻断项原文 |
| 数字卡 | 参数量、权重是否已训练、最大误差、top-1、脉冲数、能耗比、外部后端可用数 |
| 1 静态检查 | 每个阻断/警告的位置、原因、**具体改法** |
| 2 数值等价 | 验的是磁盘上的文件不是内存图；逐层脉冲率；空权重/常数输出会显式标为无效 |
| 3 外部工具链 | 同一份文件，别人的框架能不能读、读了能不能跑对 |
| 4 成本 | 能耗比、稠密等价 MAC、实际累加次数、脉冲预算 |
| 5 复现 | 一条可以直接粘贴的命令 |
| 6 边界 | **证明了什么、没证明什么**（见下） |

第 6 节是刻意写的。报告越像"结论"，越容易被当成"保证"：

> 证明了：规范语义下，导出文件与训练模型行为一致，且在非本项目实现的运行时里复现相同结果。
> 没证明：没在真实芯片上跑过；没覆盖目标板的资源约束（神经元数、片上内存、位宽）。
> **装不下和跑不对是两件事，这里只回答了后者。**

### 报告会自动拒绝"假通过"

三个已知的伪阳性都做成了显式判断，而不是靠人看：

| 伪阳性 | 表现 | 处理 |
|---|---|---|
| 空权重文件 | 全零权重 → 不发放 → 与另一个不发放的结果"相等" | `strict=True` 拒绝写盘；报告标注 `EMPTY` |
| 验内存图不验文件 | 导出 bug 丢弃权重，检查器看不见 | 先写盘再 `nir.read` 读回，`nir_source=file` |
| 常数输出 | 噪声输入下网络完全不发放，"0.0 vs 0.0" 被当成一致 | 判 `vacuous`，报告显示"这次比较不携带信息" |

## 3. 撞出来的上游问题（这部分比上面的结论更值钱）

接第三方工具链时，目标只有一个：**找一份不依赖我们代码的证据**。
结果先撞到的是两个"文件合法但没人读得了"的问题。

### 3.1 nir 1.0.x 的补丁版本之间不兼容文件

`LIF.v_reset` 是在 1.0.x 的**某个补丁版本**里加的。用 1.0.8 写出的文件，
在 1.0.4 下打开直接抛：

```
TypeError: LIF.__init__() got an unexpected keyword argument 'v_reset'
```

而 SynSense 的 `rockpool` 和 `sinabs` 都把 `nir` 钉在 1.0.4。
也就是说：**用最新版本导出，厂商工具读不了。**

我们的处理（`snndsl/backends/nir_export.py`）：`v_reset` 为 0 时不写这个字段。
这不是妥协——nir 自己的 reader 就是 `np.zeros_like(v_threshold)` 兜底，
零复位丢掉字段语义完全不变，换来的是整条 1.0.x 都能读。

```python
zero_reset = abs(float(lif["v_reset"])) < 1e-12
nir.LIF(..., v_reset=None if zero_reset else np.full(n_units, lif["v_reset"]),
        metadata={"snndsl_reset": lif["reset_mode"], ...})
```

实测：同一份文件，1.0.8 读得回来，1.0.4 也读得回来（`docs` 里的测试锁住了这条）。

> **产品含义**：兼容性不是"支持最新标准"，是"支持对方装的那一版"。
> 这个默认值现在替用户挡掉了一个本来会在他们 CI 里随机炸掉的问题。

### 3.2 rockpool 3.1.0 的 NIR 前端没跟进 nir 1.0

```
AttributeError: 'LIF' object has no attribute 'tau_mem'
```

`tau_mem` 在 nir 1.0 里改名成 `tau`，rockpool 的映射表还停在 0.x 的字段名上。
不需要我们的文件，nir 官方 API 构造一个最小 LIF 就能复现：

```python
import nir, numpy as np
g = nir.NIRGraph(nodes={
  "in": nir.Input(np.array([2])),
  "a": nir.Affine(np.ones((2,2),dtype=np.float32), np.zeros(2,dtype=np.float32)),
  "n": nir.LIF(tau=np.array([2.,2.]), r=np.array([1.,1.]), v_leak=np.array([0.,0.]),
               v_threshold=np.array([1.,1.]), v_reset=np.array([0.,0.])),
  "out": nir.Output(np.array([2])),
}, edges=[("in","a"),("a","n"),("n","out")])
g.infer_types()                      # 通过：这是合法 NIR 1.0
from rockpool.nn.modules.torch.nir import from_nir
from_nir(g)                          # AttributeError: tau_mem
```

结论：**当前任何用 nir 1.0 导出的模型，都进不了 rockpool 的 Xylo 路径。**
这是上游的事，我们修不了，但可以让用户在报告里提前知道，而不是在周五晚上知道。

### 3.3 sinabs 能读、能跑，但时间模型不同

`sinabs.nir.from_nir` 成功重建了我们的图（`Linear(784,256) → LIFSqueeze →
Linear(256,10) → LIFSqueeze`），说明**文件结构被厂商接受**。
但按它自己的时间约定执行时，输出不是二值脉冲流
（真实 MNIST 输入下峰值 1.4 脉冲/神经元/步——一条输入电流可以换出多枚"脉冲"），
与本项目的离散化不一致。

所以 `deploy` 把它标成 `load-only`（能加载，不宣称数值一致），而不是 `ok`。
**"能读"和"跑的是同一个东西"是两件事**，报告里分成两列。

### 3.4 依赖地狱是真实存在的（我们自己踩了）

为了接这三个工具链，`pip install rockpool sinabs` 把主环境里的
`nir` 从 1.0.8 降到 1.0.4、`nirtorch` 从 2.6 降到 2.0.2，
**当场挂掉我们 14 个测试**。

因此 `targets.py` 的所有探测都在**独立子进程**里跑，并支持
`SNNDSL_VENDOR_PYTHON` / `--vendor-python` 指定别的解释器。

> 这件事本身就是产品理由：一个团队同时用两家厂商的工具链，就会遇到这个。
> 编译层存在的意义之一，就是让这类冲突在**编译期**暴露，而不是在集成期。

## 4. 当前后端矩阵（可复现）

```bash
snndsl deploy examples/mnist_hw.snn --weights build_hw/mnist_hw.pt --data mnist --batch 32
```

```
--- foreign frontends (same file, same currents) ---
target                     vendor      status          detail
---------------------------------------------------------------------
nirtorch + snnTorch        neuroir     ok              max|Δ|=0.00e+00  top1=1.000  nir 1.0.8
sinabs (Speck / DynapCNN)  SynSense    load-only       能加载能跑，非二值脉冲流，时间模型不同
rockpool (Xylo) frontend   SynSense    upstream-gap    上游前端仍在读 nir<1.0 字段名（tau_mem）
rockpool modules (Xylo)    SynSense    load-only       已用 rockpool 自己的神经元跑通；11.7% 的
                                                      (神经元,时间步) 一步发多枚脉冲；文件声明
                                                      zero reset、目标只有 subtract；单独把 tau
                                                      约定从 exp 换成 Euler，脉冲位置变化 6.45%
```

最后一行是 P1 的第一个动作：**绕开读不了 nir 1.0 的前端，用 rockpool 的原生模块
重建同一张图**。算术是 SynSense 的，只有接线是我们的。它带来的不是"又多一个 ok"，
而是把"到底差在哪"拆成了三个可单独测量的量——见
[`SEMANTICS.md`](SEMANTICS.md)。一句话结论：**对齐 `tau` 的换算方式后，两家实现在
非饱和区间逐脉冲完全一致（524,288 个位置 0 处不同）；真实网络的差异主要来自
"一步该发几枚脉冲"，而标准对此没有规定。**

**给出"数值一致"的仍然只有 `nirtorch + snnTorch` 这一条**（`rockpool modules` 那条
在受控条件下也是逐位一致，但它比的是训练实现而不是我们的文件，性质不同，不能合并计数），
且其中 `Affine` 的映射由我们接管（上游 `DEFAULT_MAP` 把 bias 赋给了
`module.weight.bias`，静默丢偏置）。

诚实地说：**这仍是一条后端上的强证据，不是两条。**
它比自证好得多（不同的人写的运行时、不同的图执行器），
但"只有一个第三方后端跑通"这个事实必须写在材料里，不能写成"多后端验证"。

## 6. 下一步（P1 的第一个动作）

不是加功能，是**把"只有一个后端"变成"有两个"**，或者**上真机**。

| 选项 | 价值 | 成本 | 风险 |
|---|---|---|---|
| ~~Xylo 路径绕行验证~~ | ✅ **已做**（`targets.py: rockpool-native` + `examples/rockpool_ablation.py`） | 低 | 算术是厂商的，接线是我们的 |
| 第二个独立后端（Nengo 前端） | 排除"单后端 bug 连带自洽"的质疑 | 中（要写适配） | Nengo 的 NIR 支持也未必跟到 1.0 |
| Xylo 真机 / Rockpool XyloSamna | **最硬的证据**，可直接对厂商谈 | 高（需硬件或可用仿真器） | 硅片上还有定点化、位宽，差异只会更大 |
| 循环突触（`dense g <- h, g`） | 补最大功能空白 | 中 | 与部署无关，优先级在真机之后 |

绕行验证做完之后，3.2 那个 `tau_mem` 已经不只是"一个 bug"，而是三条规范缺口的入口。
下一步该做的不是继续加后端，是**把这三条缺口写成对 NIR 的提案**（[`SEMANTICS.md`](SEMANTICS.md) §4.3）。
理由：再多一个后端也只能证明"我们的语义没写错"，而规范不写死这三件事，
每个厂商都会各按各的理解实现——这是**上游**的问题，只有提案能改。
