# 机制级调研：别人做对了什么，我们该拿什么

> 这份文档和 [`ECOSYSTEM.md`](ECOSYSTEM.md) 分工不同。那份按**层**排（运行时/IR/硬件），
> 数 stars，回答"格子空不空"。这份按**机制**排，回答一个更具体的问题：
> **同一件必须解决的事，各家分别怎么做的，谁的做法值得我们抄，抄过来要付什么代价。**
>
> 数据来源：各项目文档与源码、SNN-MLIR 论文（[arXiv 2606.09213](https://arxiv.org/html/2606.09213v1)）、
> NIR 论文（[arXiv 2311.14641](https://arxiv.org/pdf/2311.14641)）、
> Rockpool→Xylo 部署管线（[arXiv 2412.11047](https://arxiv.org/pdf/2412.11047v1)）、
> Xylo 硬件规格表。抓取于 2026-10。
>
> **本仓库自己的实测数字用 `实测` 标注**，脚本在 `examples/probe_target_cost.py`。

## 0. 一句话结论

调研做了两轮，结论是反的，所以先说结论：

**第一轮**（读文档）我准备提"量化 scale 对齐"和"tau 离散化"两个机制，因为它们分别被
SNN-MLIR 和 Rockpool 显式解决了，而我们没有。听起来非常对。

**第二轮**（在 MNIST MLP 上实测）两个机制都**近乎不成立**：int8 权重只掉 **0.02pp**；
tau 在 1.5–4.0 之间扫（记忆强度变化 2.7 倍）只动 **0.09pp**。原因很直接——

> 一个记忆强度变化 2.7 倍而精度不变的网络，它的 LIF 层其实只是在做 `relu`。
> 说它"是 SNN"没错，说它"用了 SNN 的时间语义"是错的。

（同一张表里 tau = dt 会掉 1.22pp，因为那一步**完全去掉了记忆**。
所以准确的说法是：这个网络的记忆**值 1.2 个点**，但记忆**多强**一分钱不值。
两个量必须分开，混在一起看就会得出相反的结论。）

**第三轮**（换到有真实时间结构的手势任务）结论翻转：记忆强度变化直接掉 **10.00pp**。

所以真正的结论不是"该抄哪个机制"，而是：

| 网络 | memory_value（tau=dt，无记忆） | memory_strength（tau∈[1.5,4]） | 判读 |
|---|---:|---:|---|
| MNIST MLP（rate 编码） | 1.22pp | **0.09pp** | LIF 层是 `relu` 的壳 |
| 手势网（2 极性 8 步） | 4.58pp | **10.00pp** | 时间语义真的在承重 |

**同一个扰动，两个网络差 111 倍。** 这意味着：

> **"这个网络的时间语义值多少钱"是一个编译期可测、今天没有工具去测的量。**
> 测它只需要一次 tau 扫描，成本几十秒，而它同时决定三件事：T 该设多少、
> tau 在目标芯片上能不能被量化、这个网络的"SNN 优势"是真优势还是壳。

下面每个机制提案都从这条结论长出来。

## 1. 逐家：独有机制、边界、可拿的东西

只列**在别处没有**的机制。通用能力（能训练、支持卷积）不列，因为抄不了也没必要。

### 1.1 SpikingJelly —— 时间维的两种传播顺序是可选参数

**独有机制**：`step_mode` 属性，让同一个网络在**逐时间步**（DFS）与**逐层**（BFS）
两种计算图构建顺序之间切换。BFS 下把 T 折进 batch 维处理无状态模块，有状态模块做
kernel fusion。作者的定位很明确：DFS 便于建循环连接、内存不随 T 增长；BFS 快，
因为时间步被合并进了 batch。

**边界**：这是**用户手动选的**，不是编译器推的。用户要在每个模块上设对 `step_mode`，
设错了不会报错，只会慢，或者更糟——在有状态模块上误用 BFS 得到错的结果。

**可拿的**：判断"哪些层可以把 T 折进 batch"是个**纯图论问题**：
无状态算子（dense / conv / pool / 逐元素）跨时间步无依赖，可以折；有状态算子
（任何 neuron）有 `v` 跨步携带，不能折。
我们的 IR 已经有完整的节点类型和 buffer 分配信息，**判定这件事不需要用户参与**。
→ 机制 M3。

**不拿的**：它的 CUDA auto-gen（`auto_cuda` 里按神经元类型生成 kernel）。那是运行时
该做的事，我们在 NIR 之上，做了也打不过。

### 1.2 snnTorch —— 递归形式省掉整条 trace

**独有机制**：神经元模型写成递归函数 `spk, mem = lif(cur, mem)`，所以算梯度**不需要
存所有时间步的膜电位**。这是设计取舍里最省内存的一种，也是它能"在 CPU 上训中小网络"
的原因。

**边界**：递归形式意味着图是**逐调用展开**的，`torch.jit.trace` 在 T=32 时给
137 个节点（本项目 README 实测）。省了内存，赔了静态性。

**可拿的**：它导出的 NIR 是**第三方 NIR 的真实来源**，而它的导出路径有一串已公开的坑：

| 坑 | 性质 | 后果 |
|---|---|---|
| 标量参数（`Leaky(beta=0.9)`）在新版 NIR 里不合法 | 类型检查变严 | 老版本导出的图**新版本读不了** |
| `RLeaky` 不支持导出 | 静默跳过 | 循环网络导出去少一层 |
| 子图里的 `LIF` 不支持导入 | 单向 | 导出的循环网络**导不回来** |
| `Flatten` 让 `infer_types` 报 type mismatch | 需 `ignore_dims=[0]` 绕 | 首维语义漂移 |
| `v_reset` 参数缺失（issue #384） | 语义丢失 | 复位行为不可知 |

这些坑的共同点：**导出成功、加载成功、数字错**。这正是本项目 `deploy --verify`
存在的理由，但它今天只验自家产物。→ 机制 M5。

### 1.3 Rockpool + Xylo —— 把"能不能上芯片"变成一张有数字的规则表

**独有机制**：`xylo.mapper(graph)` 把图映射到**具体芯片的资源**，`config_from_specification`
**校验并拒绝**不合规的配置。Xylo-Audio 2 的硬规格（来自部署管线论文 Table 1）：

| 约束 | 值 | 我们今天的对应物 |
|---|---|---|
| 输入通道 | ≤ 16 | — |
| 隐层 LIF 神经元 | ≤ 1000 | ❌ 只查 NIR 能否表达 |
| 输出 LIF 神经元 | ≤ 8 | ❌ |
| 每神经元输入突触组 | ≤ 2 | ❌ |
| 权重位宽 | 8 | ⚠️ `quant = int8` 只是元数据 |
| 状态（膜电位/突触电流）位宽 | 16 | ❌ |
| decay 参数位宽 | **4 bit，max 15** | ❌ |
| 最长有效时间常数 | 32768·dt | ❌ |

倒数两行是本次调研最重要的发现：

> **decay 是 4-bit bit-shift，所以芯片上能表示的 tau 只有 16 个值：`{2^k · dt, k=0..15}`。**
> 我们在 DSL 里写 `param tau = 3.0`，训练收敛，导出成功，NIR 合法，
> 芯片上这个值**不存在**。

实测代价（§2）：tau 训练在 3.0、只能落到 2.0 时，手势任务 **93.75% → 90.00%（-3.75pp）**。

**边界**：绑定单一厂商。`mapper` 的规则是 Xylo 的，不是通用的。

**可拿的**：**规则本身是数据，不是代码。** 把"某芯片允许什么"写成一张表，
编译期逐条求值，就能在**不买板子**的前提下回答"这个网络上不上得去、差在哪一条"。
我们今天做的是"NIR 能不能表达"——那是标准的能力边界，不是芯片的采购约束。
这两件事差一个数量级的具体性。→ 机制 M2。

**不拿的**：位精确仿真器 `XyloSim`。我们已经有 `nir_sim`（浮点解释器），做定点位精确
仿真需要先有量化语义，那是 M4 之后的事。

### 1.4 SNN-MLIR —— type-polymorphic op，一个 op 服务浮点和定点

**独有机制**（三个，按可抄程度排）：

1. **一个 op 携带两套参数**：`cur_decay_float` 与 `cur_decay_int`（Q12 定点），
   lowering 按操作数元素类型选一套，另一套保持默认。一套 verifier、一个 lowering
   pattern 在 f32 与 i32 间共享，**没有并行的浮点/整数 op 集**。
2. **`snn.rescale`：量化 scale 对齐**。权重按 2 的幂量化（`w_scale = floor(log2(ratio))`，
   只存指数），神经元状态用 Q12，两者 scale 不同，直接相连会静默破坏动力学。前端在每条
   synapse→neuron 边上插入 `shift = d_scale - w_scale` 的整数移位。
   论文明确说这个机制**在 NIR 里没有对应物**——因为 NIR 模型里根本不存在量化 scale。
3. **memref-based 而非 SSA value**：因为神经元状态要跨时间步持久化、原位更新。
   这一点我们自己发的 MLIR 也是这么做的（膜电位作函数参数），但**理由是他们写清的**。

**实测的量化代价**（他们的表，供对标）：

| 网络 | float32 | int8 | 逐位精度 | 加速 | 权重压缩 |
|---|---|---|---|---|---|
| snn_oxford（Lava-DL 导出） | 100% | 99.59% | 99.585% | 1.25× | 4.20× |
| snntorch（snnTorch 导出） | 100% | 92.00% | 92.000% | 1.34× | 3.90× |

注意第二行：**同一个后端、同一个量化方案，换个来源框架，逐位精度从 99.6% 掉到 92.0%。**
论文自己把原因归给"网络本身对量化的敏感度不同"，但没说怎么在导出前预测它。

**边界**（他们自己列的，全部强制报错而非静默假设）：无卷积 op、仅线性链（不支持分支/
残差/循环）、batch size = 1、层内神经元参数必须一致。

**可拿的**：第 2 条——**但位置要往前挪**。他们在 NIR 之后插入 rescale，那时权重已经
训完了，只能事后补偿。我们在训练**之前**就有 IR，可以让训练直接产出 2 的幂权重（QAT），
从源头消除 scale 不匹配。这是本项目相对他们唯一的结构性优势：**他们看不到训练**。

**不拿的**：注册自定义 MLIR dialect（理由已在 ECOSYSTEM.md §7.6 L2 说清，不重复）。

### 1.5 NIR —— 它自己承认的失配三分类

**独有机制**：不是技术，是**分类法**。NIR 论文把跨平台失配归成三类，并给出量化结果：

1. **神经元模型实现差异**：脉冲与复位的时序、离散化选择不同
2. **量化**：权重量化引入舍入，改变活动
3. **非确定性**：异步硬件（Speck、SpiNNaker2）不保证单事件确定性

结论里最硬的一句：**SNN 循环网络（SRNN）跨平台差异显著大于前馈网络**，
因为"循环连接会放大动力学的细微差异"，网络"被训练成对特定模拟器的细节敏感"。

这直接支持我们自己的实测：手势网络的记忆强度敏感度是 10.00pp，
MNIST MLP（退化成静态分类）在同一扫描上是 0.09pp。**两种网络不是同一类东西，
却用同一套"equivalent / not equivalent"判据在描述。**

**可拿的**：把 fidelity 报告从**二元判定**改成**归因**。现在报
`equivalent: false, max|Δ|=0.03`；应该报
`不一致，归因：tau 离散化（tau 3.0 在目标上不存在，落到 2.0）`。
前者要人去查，后者直接是改法。

**边界**：NIR 明确不管离散化、量化、调度（论文原话：*"It intentionally says nothing
about how that model is discretized, quantized, scheduled, or compiled"*）。
这是空位，但**空位不等于我们的地盘**——SNN-MLIR 已经公开说要和 NIR 团队一起提
量化/离散化规范。谁先拿出**带测试向量的规范提案**，谁定义这块。我们有材料
（tau 四种离散化导致 1.19%–16.5% 脉冲错位），但还没写成提案。

## 2. 本仓库实测：两次相反的测量

脚本：`examples/probe_target_cost.py`（`实测`，MNIST MLP + 手势网，CPU，无训练重跑）。
两个网络都用**同一份训练好的权重**，只改编译期常量后重新编译，所以测的是纯部署侧漂移。

### 2.1 tau 漂移

Xylo 类芯片上 tau 只能取 `2^k · dt`。下表模拟"训练时的 tau 在目标上不存在"：

| 训练 tau | 最近可表示值 | MNIST MLP（首层 rate 编码，静态任务） | 手势网（2 极性 8 步，membrane 读出） |
|---:|---:|---:|---:|
| 1.00 | 1.00 | 95.30%（**-1.22pp**，无记忆） | 89.17%（**-4.58pp**） |
| 1.50 | 1.00 | 96.46%（-0.06pp） | 92.08%（-1.67pp） |
| 2.00 | 2.00 | **96.52%**（基准） | **93.75%**（基准） |
| 2.50 | 2.00 | 96.51%（-0.01pp） | 93.33%（-0.42pp） |
| 3.00 | 2.00 | 96.43%（-0.09pp） | 90.00%（**-3.75pp**） |
| 4.00 | 4.00 | 96.46%（-0.06pp） | 83.75%（**-10.00pp**） |

两列的差别是这篇文档最重要的一个数字，但要读对：

- **右侧有清晰的方向性**：tau 偏离 2.0 越远掉得越多，只有训练时的值最好。
  这是"时间语义在承重"的签名。
- **左侧没有方向性**：1.5–4.0 全在 ±0.09pp 内乱跳（10000 张测试集，95% CI 约 ±0.4pp，
  所以这四行彼此不可区分）。唯一的例外是 tau=1.0——它把泄漏系数 `1-dt/tau` 变成 0，
  **完全去掉记忆**，掉 1.22pp。这恰好证明左侧的网络"有记忆但不用记忆强度"。

所以正确的结论不是"tau 离散化是普遍痛点"（它对一半的 SNN 无所谓），而是：
**先量这个网络在不在乎，再决定要不要为它的 tau 花钱。** 见 M1。

### 2.2 int8 量化的真实代价

当前工具（`runner.py`）做 int8 PTQ 后**只报压缩率**，不报精度。补上这个数：

| 网络 | 方案 | 精度 | 代价 | 压缩 |
|---|---|---|---:|---:|
| MNIST MLP | per-channel int8 | 96.52% → 96.50% | -0.02pp | 3.90× |
| MNIST MLP | per-tensor int8 | 96.52% → 96.50% | -0.02pp | 3.90× |
| 手势网 | per-channel int8 | 93.75% → 92.92% | -0.83pp | 3.76× |
| 手势网 | per-tensor int8 | 93.75% → 93.33% | -0.42pp | 3.76× |

手势网的 240 张测试集上，95% 置信区间约 **±3pp**。所以 per-channel 与 per-tensor 的差别
（0.42pp）**不可区分**，两种方案都能用。

但结论不是"量化无害"，而是：**"压缩 3.76 倍"这句话单独出现时没有决策价值。**
3.76× 和 3.90× 的差别，比"精度代价是否落在噪声内"小一个数量级。
报告应该报后者。

## 3. 五个机制提案

每个都写：动机（来自谁）、为什么是我们做、最小实现、验收、证伪条件。
**按性价比排序**，M1 最该先做。

### M1 · 时间维度使用度分析（`snndsl analyze --temporal`）

**动机**：§2.1 的 111 倍差距。没有任何工具问"这个网络用没用时间"。
SpikingJelly 让用户手动选 `step_mode`，隐含假设用户知道自己要什么模式；
实际上用户不知道自己的网络是 `relu` 还是真的在积分。

**为什么是我们**：需要同时有 IR（知道哪些节点有状态）、有数据（能跑前向）、
能改编译期常量重编译（扫描 tau）。这三样只有我们这一层同时具备。

**设计**：三个探测，全部无训练。核心是把 §2.1 的一个数字拆成两个独立的量：

| 量 | 定义 | 它回答什么 |
|---|---|---|
| `memory_value` | `Δacc(tau = dt)` | 记忆本身值多少点（=0 时 LIF 就是 `relu`） |
| `memory_strength` | `max\|Δacc\|` over `tau ∈ [1.5, 4]` | 记忆的**强度**被用到多少 |

判读表（两个量必须一起看，任一单独看都会误判）：

| `memory_value` | `memory_strength` | 判读 | 建议 |
|---:|---:|---|---|
| ≈0 | ≈0 | 没有记忆 | T=1，删掉 neuron 层 |
| >1pp | ≈0 | 有记忆但不用强度 | LIF 层可合并；tau 无所谓 |
| >1pp | >1pp | 时间语义在承重 | tau 必须保真，见 M2 |

另两个探测作为交叉验证：

| 探测 | 做法 | 用途 |
|---|---|---|
| 时间消融 | 只保留前 `T/4, T/2, T` 步的输入 | 精度随有效步数的曲线，用来定 T |
| 状态消融 | 每步强制 `v := 0` | 与 `memory_value` 应为同一量级，对不上说明有别的状态在起作用 |

对 `mnist_mlp` 的预期输出（实测已确认）：

> 这个网络的 `memory_value` = 1.22pp、`memory_strength` = 0.09pp。
> 它的 LIF 层保留了"有记忆比没记忆好 1.2 个点"，但记忆的时间常数完全不敏感，
> 等价于一个带泄漏的 `relu`。T 可以降到 1，tau 在目标芯片上怎么量化都无所谓。
> 但它**不该**被当作"SNN 低功耗优于 CNN"的证据——它的稀疏性来自 rate 编码，
> 不是来自时间编码。

**最小实现**：`examples/probe_target_cost.py` 里的扫描逻辑（约 80 行）搬进
`snndsl/analysis/temporal.py`，接 `snndsl analyze` 子命令。

**验收**：在 `mnist_mlp` 上报 `memory_strength = 0.09pp`，在 `gesture_snn` 上报
`10.00pp`，两者都进测试固定住（脚本已能复现，见 `--gesture`）。

**证伪条件**：如果做出来发现"大多数真实 SNN 都判 `strength≈0`"，那结论不是工具有问题，
而是**这个生态里大量"SNN"没有用时间**——这本身是个值得写出去的结果，
但会削弱"SNN 低功耗"的叙事，要准备好面对。

### M2 · 目标规则集（`snndsl targets/*.yaml` + `--target xylo`）

**动机**：Rockpool 的 `mapper()` 证明"把芯片约束写成数据"是可行的、且是用户真正想要的。
我们今天 `deploy` 查的是"NIR 能不能表达"——标准的能力边界，不是采购约束。
两者差一个数量级的具体性：`MaxPool2d` 不存在是标准问题，`tau 只有 16 个可选值`是芯片问题。

**为什么是我们**：因为没有别人在做**跨厂商**的这一层。Rockpool 的规则是 Xylo 的，
BrainChip 的规则在闭源 MetaTF 里，Loihi 的规则随 Lava 一起归档了。
一张中立、可 diff、可被厂商 review 的规则表，是生态缺的那件东西。

**设计**：规则表是 YAML，每条规则带**求值器和证据**：

```yaml
target: xylo-audio2
source: "arXiv 2412.11047 Table 1"
rules:
  - id: hidden_neurons
    limit: 1000
    eval: count(nodes where op == neuron and role == hidden)
  - id: tau_representable
    kind: enumerated
    allowed: "2^k * dt, k in 0..15"
    eval: per neuron layer, snap(tau) and report drift + accuracy delta   # 需要校准集
  - id: weight_bits
    limit: 8
    eval: quantization_report(per_channel=True).max_rel_error
  - id: state_bits
    limit: 16
    eval: membrane_range_over_calibration_set / 2^16
```

关键在 `tau_representable` 这一条：它不是静态检查，**需要校准集**才能算出代价。
这就是我们的差异——静态检查谁都能做（查表），"这条规则违反了会掉多少精度"
只有能跑数据的人能做。

**验收**：对五个现有示例各跑一遍 `--target xylo`，输出一张表：哪条规则违反、
违反后精度掉多少。其中一个必须报出"tau 不可表示"。

**证伪条件**：如果 SynSense 公开的规格与论文 Table 1 不一致，或者厂商明确表示
"tau 的实际表示不是 2^k"，那这条规则作废，但**规则表的机制不变**——换数字即可。
所以这个机制的风险很低，这是它排第二的原因。

### M3 · T-Folding pass（把无状态层的 T 折进 batch）

**动机**：SpikingJelly 的 BFS 模式实测比 DFS 快（作者的 kernel fusion 论证）。
但它是**用户手动选的**，我们是编译器，可以自动判定。

**为什么是我们**：判定条件在 IR 上是纯图论：一个节点可折，当且仅当它的所有输入
都来自可折节点，且它自身无跨步状态。IR 里 `neuron` 节点有 `state`，`dense/conv/pool`
没有。**这个判断不需要任何领域知识，也不会判错。**

**设计**：新增 pass `fold_time`，把可折子图的输入 reshape 成 `(T*B, ...)`，
一次 GEMM 算完 T 步，再 reshape 回 `(T, B, ...)`。语义完全等价（无状态 ⇒ 可交换），
所以可以用逐位比较验证。

**验收**：
- 数值：折与不折的脉冲轨迹逐位相同（`max|Δ| = 0`）
- 性能：GPU 上 T=8、MNIST MLP 的每样本延迟下降；CPU 上可能反而变慢（要如实报）
- 边界：`pool` 若为 `max` 且下游有 neuron，**不能折**（池化窗口跨步语义需确认）

**证伪条件**：如果折了之后在 CPU 上一致地更慢，且 GPU 上提升 < 10%，
这个 pass 的复杂度就不值——那就只保留"报告哪些层可折"的诊断，不真折。

### M4 · 量化报告改报精度代价（替换现在的"压缩率"）

**动机**：§2.2。当前 `runner.py:279` 做完 PTQ 后写进 metrics 的只有
`bytes_fp32 / bytes_quantized / compression`。这是**成本侧**的数字，
没有**收益侧**（精度）的数字，所以它无法支撑任何决策。

Spiker+ 的做法更彻底：量化位宽是**搜索出来的**，不是固定 8 bit。
SNN-MLIR 的实测则说明同一方案换个网络代价能差 7 个点（99.59% vs 92.00%）。

**设计**：

```
量化报告 = { 方案, 位宽, 精度(before→after), Δ, 测试集大小, 95% CI, 逐层 rel_error }
```

三件事必须做：
1. **报 CI**。240 张测试集上 0.42pp 的差别不可区分，报告必须说这句，否则就是误导。
2. **扫位宽**。至少 `{8, 4}`，输出 `位宽 → (压缩率, Δacc)` 曲线，让用户自己选点。
3. **逐层误差归因**。哪一层量化后 rel_error 最大，指出来。

**验收**：两个网络 × 两个位宽，产出四行数，其中手势网 T=8 的 int8 那行必须是
`-0.83pp`（可复现）。CI 用 bootstrap，别用正态近似。

**证伪条件**：如果扫完发现所有网络在所有位宽下 Δ 都 < 1pp，那说明**这个检查不必要**，
SNN 的 0/1 激活确实让量化很安全。那就把报告压回一行，别做曲线。
——这个可能性不低，所以排在第四。

### M5 · 第三方 NIR round-trip 破坏性测试（conformance suite）

**动机**：§1.2 的五条坑。它们的共同点是**导出成功、加载成功、数字错**。
今天没有任何工具在管这件事：NIR 只保证格式合法，snnTorch 只保证自己的测试过。

**为什么是我们**：`deploy --verify` 已经具备全部零件（读回文件、独立解释器、
逐样本比、归因）。缺的只是**把输入从自家产物换成别人的产物**。
这是 ROADMAP §7.4 路径 B 的具体化，也是把检查能力从"自证"变成"他证"的唯一路径。

**设计**：构造 12 个**语义已知的极小网络**（各 3–10 个节点），每个配一份
"正确答案"（golden pulse trace）。用 snnTorch / Rockpool / 手写 NIR 各导出一次，
读回来逐脉冲比。产出是一张公开表：

| 来源 | 网络 | 声称 | 实际 | 归因 |
|---|---|---|---|---|
| snnTorch `export_nir` | Flatten→Linear→LIF | 导出成功 | 首维语义漂移 | 需 `ignore_dims=[0]` |
| snnTorch `export_nir` | RLeaky 循环 | — | 静默少一层 | 不支持 |
| … | … | … | … | … |

**验收**：至少 3 个真实失真被自动检出，且每个有归因、有最小复现（10 行以内）。

**证伪条件**：如果 12 个网络全部 round-trip 无损，那说明这层不需要我们，
应该转去 M1/M2。**但这个结果本身有价值**——它会推翻我们"导出普遍有损"的叙事。

## 4. 明确不做的

调研里看到不少"看起来该做"的东西，逐条记下拒绝理由，免得下次重新讨论。

| 候选 | 来自 | 不做的理由 |
|---|---|---|
| 注册自定义 MLIR dialect | SNN-MLIR | 方言要求语义无歧义，而本项目存在的理由是**语义有歧义**（tau 四五种离散化、reset 形式不一致）。选定一种就成了"第 N 个实现"。详见 ECOSYSTEM.md §7.6 |
| HDL / VHDL 生成 | Spiker+ | 需要量化语义 → 时序约束 → 综合验证，是另一个项目的工作量。而且 Spiker+ 已经做了，且做得比我们能做的深 |
| SymbiYosys 形式验证 | SC-NeuroCore | 需要 HDL 作为对象。我们可以降级做"区间等价"（膜电位上下界传播），但那是 M2 之后的事 |
| 位精确硬件仿真器 | Rockpool `XyloSim` | 依赖定点语义（M4）和具体芯片时序。我们做参考解释器，不做目标仿真器 |
| CUDA kernel 自动生成 | SpikingJelly | 运行时该做的事，我们在 NIR 之上，做了也打不过 |
| 重写 lowering 到 LLVM | SNN-MLIR / SNAX | 已论证（ECOSYSTEM.md §7.2），一人项目长期打不过 xdsl/MLIR 基建 |
| 支持循环突触 / 延迟线 | NIR（有 `Delay`） | 会打破"静态 DAG + 单一时间循环"的全部假设，等于重写编译器。**但应该在 GAPS 里明确标为"不支持"，而不是沉默** |

## 5. 顺序与理由

```
M1 时间维度使用度   ← 先做。它决定后面三个机制是否值得做。
   │
   ├─ 若判 used ──→ M2 目标规则集（tau 真的会漂，需要拦）
   │                  └──→ M4 量化代价（tau 之外还有位宽）
   │
   └─ 若判 none ──→ M4 降级为一行报告，M2 只查静态规则

M3 T-Folding        ← 与 M1 无关，纯性能。单独排期，有明确证伪条件。
M5 conformance      ← 最贵（要装三个框架），但产出最公共。适合有外部关注时做。
```

**为什么 M1 最先**：它成本最低（60 行、无训练、几十秒），但它**改变对其他机制的判断**。
做完之后如果发现大多数网络判 `none`，M2 和 M4 的优先级都要下调——
那时真正值钱的结论是"这些 SNN 没用时间"，而不是"给它们做量化对齐"。

这正是这次调研最大的收获：**先问网络用没用时间，再决定要不要为它的时间语义花钱。**

## 6. 这份调研的局限

- **只测了两个网络**，都是本仓库的示例。判 `used` / `none` 的阈值（1pp）是拍的，
  没有在真实数据集（DVS128 Gesture、SHD）上校准过。
- **Xylo 的 tau 表示是从论文 Table 1 推出的**（4-bit bit-shift decay + 最长 32768·dt），
  没有对着 SynSense 的源码或手册逐条核。这条如果错了，M2 的数字要改，机制不变。
- **没有厂商确认**：规则表的价值取决于厂商认不认这张表。这件事只能靠接触，
  不能靠写文档。它是 ROADMAP P0-2（12 场访谈）的一部分，仍然没做。
- **没测 SHD / DVS128**：那两个是真正有时间结构的标准数据集，是 M1 阈值的唯一可靠校准来源。
  缺这一步，M1 的判定会在"边缘网络"上给出可疑结果。
