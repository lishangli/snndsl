# 生态调研与定位

> 目标：用可核查的数据回答三个问题——我们在哪、谁在旁边、凭什么这个位置是我们的。
> 所有 GitHub 数据抓取于 2026-10，用 `api.github.com` 公开接口；市场数据引自公开报告。

## 1. 结论

**这个行业缺的不是运行时，也不是硬件标准，而是两者之间的编译层。**

上层（写网络）有约 5,000 stars 的关注度，底层（硬件 IR）只有 190。
写这份文档时（2026-10）中间层是空的；同一时期它已经不空了，只是空的位置变了——
见 [§7](#7-mlir-路线与-risc-v-目标层)。一句话：**从 NIR 往下有人了，
从源码往上仍然没有人**。原文的判断保留下方，因为它仍然解释了这个空缺是怎么形成的：

- 运行时库团队没有动力做硬件导出（要处理各家芯片的时序细节，收益归硬件厂商）
- 硬件厂商没有动力做跨硬件的中立编译器（等于帮竞争对手降门槛）
- 学术界做了标准（NIR），但标准需要前端才有用，而写前端不是发论文的题材

Intel 在 2026 年 5 月归档整个 Lava 框架，官方说明下一代 SDK 将 **"built on open-standard AI frameworks"**，
目的是 **"lower the adoption barrier"**。这是这个判断最硬的一份背书：连最有资源的硬件厂商都承认，
自建封闭工具链这条路走不通。

### 2.2 关注度的断层

把 stars 按层加总，断层非常明显：

```
运行时 + 仿真器   ████████████████████████████████████████  7,224
厂商工具链       ███                                         183  (已归档)
硬件 IR          ████                                        216
编译层            ▏                                            0
```

**上层比下层热 33 倍。** 这个比例说明两件事：

1. 想用 SNN 的人很多（需求真实存在）
2. 能把 SNN 送上硬件的人极少（供给几乎为零）

一个健康的生态，这三层应该是同一个数量级。差 33 倍，说明中间那一层是瓶颈，
而不是需求不足。这正是"NIR 有了标准但没人写前端"的量化表现。

## 3. 逐家对比：他们为什么不占这个格子

### 3.1 运行时库（snnTorch / SpikingJelly / Norse）

**它们的图是动态的。** 你写 `for t in range(T)`，Python 解释器逐句执行，
没有任何一个时刻存在一张完整的、可分析的图。后果：

- 编译期无法回答"这个网络要多少内存"——只能在训练完、跑起来之后测
- 无法做图优化（算子融合、buffer 复用、时间步调度）
- 无法导出硬件：NIR 要求图固定，动态图给不出来

这不是它们做得不好，是**用 PyTorch 模块组合的方式，结构上就拿不到静态图**。

我们的做法：先建静态 IR，再从 IR 生成 PyTorch 代码。同样能训练，
但 IR 在手，优化和导出都成为可能。物理上是同一个计算，只是顺序反过来。

### 3.2 Sango（Sandia 国家实验室）

最接近我们的一层，但方向不同。Sango 用 Python 类组合构造网络
（`Network` / `NodeGroup` / `EdgeGroup`），底层是 NetworkX 图 + NumPy 数组。

**它是构造 API，不是编译器。** 没有 IR、没有 pass、没有代码生成、没有硬件导出。
它解决的是"怎么优雅地拼出一个大网络"，不是"怎么把这个网络变成可执行、可优化的东西"。

这两件事可以共存——事实上 Sango 的 API 设计（层级命名、别名、拓扑排序）
对我们的文本前端有借鉴价值，值得读它的实现。

### 3.3 snn-compilation-infrastructure（独立开发者，2025-12）

**方向完全一致**：前端 DSL → SNN IR → 优化 → TVM 后端。

但状态是：`Getting Started: TBD`、`Quick Example: TBD`、`Installation: TBD`。
仓库里只有 ANTLR 的 lexer/parser 草稿。

这件事有两面：
- 好的一面：我们的方向被独立验证了，不是自嗨
- 需要警惕的一面：这个方向有人试过，卡在了从"能解析"到"能跑通"之间

我们的差异：**已经跑通了**。97.21% 的 MNIST、41 个测试、NIR 能导出也能读回、
双前端权重互通。实现了的东西比计划了的东西值钱。

### 3.4 NIR 生态

NIR 是 2024 年 Nature Communications 的成果，四个硬件平台在读它。
但整个生态只有 **216 stars**，而且：

- `NIRTorch` 只做张量格式转换，不含图语义
- 没有官方前端
- 没有官方参考解释器（我们为此写了 `snndsl/backends/nir_sim.py`）

**这对我们是极好的位置**：标准已经存在并被接受，但标准的工具链是空的。
我们不需要说服任何人接受 NIR——只需要成为它最好用的前端。

### 3.5 Intel Lava 的归档

2026 年 5 月，Intel 归档了全部 Lava 仓库，官方说明：

> "Intel is developing the next-generation Loihi architecture and SDK... 
> The new SDK will be built on open-standard AI frameworks to lower the adoption barrier."

三条信息：

1. **封闭工具链失败**：Lava 有 Intel 的资源，仍然没起来
2. **转向开放标准**：下一代要基于开放框架——这几乎肯定意味着 PyTorch + NIR 这类开放 IR
3. **门槛是核心矛盾**：官方用词是 "lower the adoption barrier"，和我们解决的问题完全重合

这是一个窗口：**硬件厂商主动放弃了工具链，正在寻找替代品。**

                    └──────────────┬──────────────┘

                          ↓                 ↓
              ┌───────────────────┐  ┌──────────────┐

              └───────────────────┘  └──────────────┘
                     ↑                      ↑
              运行时库的地盘          硬件厂商的地盘

**一句话定位**：不是更好的 SNN 库。原本写的是"是 SNN 的编译器"——这句话现在有一半
被 MLIR 路线拿走了（§7）。准确的说法是：**从源码到 NIR 这一段的编译器，加上一段没人在做的
跨实现对照**。前端是我们的，lowering 之后的事，性能上打不过 MLIR，也不该打。

## 5. 用户是谁，痛点是什么

### 5.1 三类用户，按付费意愿排序

**A. 神经形态硬件厂商（付费意愿最高）**

痛点：客户买了芯片写不出代码，退货率高、复购低。
他们需要的不是更好的芯片，是"能让客户第一天就跑起来"的工具链。

我们提供：一个能生成他们硬件指令的前端。我们是他们的销售加速器，不是竞争对手。

**B. 做边缘 AI 的产品团队（付费意愿中等）**

痛点：想在低功耗设备上用 SNN，但不确定能不能落地。
典型问题：*"我这个模型放到 Xylo 上到底能不能跑？省多少电？精度掉多少？"*

今天回答这个问题的方式是：买开发板、手工移植、测。周期以月计。

我们提供：`snndsl deploy --verify`，编译期给出答案。

**C. 学术研究者（付费意愿低，但决定生态）**

痛点：复现别人的 SNN 论文，要重写代码；论文里的网络和硬件上的网络不是同一份代码。
想要：一份描述，两处产出，且保证一致。

我们提供：双前端 + 权重互通 + 可读的生成代码。他们是开源版的核心用户，
也是把 `.snn` 变成论文附录默认格式的人。

### 5.2 痛点排序（按"今天无解"的程度）

| # | 痛点 | 今天怎么办 | 我们的答案 | 状态 |
|---|---|---|---|---|
| 1 | 训练的网络和硬件上的网络不是同一个 | 手工移植，出问题再查 | 静态 IR + 数值等价验证 | ✅ 已实现 |
| 2 | 不知道模型的部署成本 | 训练完跑 profiler | 编译期成本模型 | ✅ 已实现 |

## 7. MLIR 路线与 RISC-V 目标层

§1–§6 写于中间层还空着的时候。补记这一节，因为现在那里站着两个项目，而且其中一个的论文
第一句话和我们 README 的第一句话几乎一样：NIR 解决了交换，但没人做中间那层可变换的表示。

### 7.1 谁在那

| 项目 | 形态 | 入口 | 出口 | 与我们重叠 |
|---|---|---|---|---|
| [SNN-MLIR](https://github.com/INTERA-GROUP/snn-mlir) | MLIR dialect + 编译器 | **`.nir`** | 裸机 C11 | 整个"编译层"主张 |
| [SNAX-MLIR](https://github.com/KULeuven-MICAS/snax-mlir) | xdsl 编译器 + RISC-V 集群 | `linalg` on `memref` | RISC-V 可执行文件 → **verilator 模型** | 目标平台这一段 |
| 本项目 | DSL + 自有 SSA IR + 多后端 | **`.snn` 源码** | PyTorch / NIR / MLIR 文本 | 源码到 NIR |

把这张表和 §2.1 放一起看，中间层不是空的，而是**被一条线分成了两半**：

```
   写网络 ──→ [ .snn / Python / PyTorch ] ──→ NIR ──────────────→ 芯片
                    ↑                         ↑         ↑
              我们在这一段              SNN-MLIR 从这起  厂商工具链
```

SNN-MLIR 和 SNAX 都从 **NIR 或更低**起步；我们和所有运行时库都在 **NIR 之上**。
两边都自称"编译层"，但说的是不同的半段。

### 7.2 结构性差异，不是完成度差异

| 维度 | MLIR 路线 | 本项目 | 谁赢 |
|---|---|---|---|
| 基础设施 | canonicalize / CSE / bufferization / linalg，上千个项目压过 | 5 个自己写的 pass | **他们**，且差距在扩大 |
| 代码生成 | 真下到底：C11 / LLVM IR / RISC-V 二进制 | 停在可读 Python + NIR + MLIR 文本 | **他们**，嵌入式场景完胜 |
| 互操作 | 能被 IREE / torch-mlir 加载 | 现在能**发** `builtin/func/memref/arith/scf` 文本，仍不能**收** | 他们，但差距从"没有"变成"单向" |
| 覆盖面 | 动态形状、控制流、多 kernel 由 MLIR 兜底 | 静态形状、无环 DAG | **他们** |
| 版本成本 | 追 MLIR 版本是长期税，out-of-tree 每年都要修 | `pip install -e .`，numpy 就能编译 | 我们 |
| 前端 | 没有前端，用户得先有 `.nir` | 有，25 行能写一个网络 | 我们，但这是他们主动不做的 |

直说：**如果评比标准是"谁的编译器更完整"，我们输**，一个自己实现 pass 的一人项目长期打不过
xdsl/MLIR 那套被压过上千次的基建。这条不辩解。

### 7.3 verilator 模型给了什么，又不给什么

SNAX 的 verilator 模型是这套生态里唯一的 **RTL 级参照物**：它跑的是 RISC-V 可执行文件，
出来的是周期精确的波形和性能计数。这是软件仿真器给不了的东西——定点截断、时钟分频、
SRAM bank 冲突、双缓冲时序，全都发生在这一层。

但它**不能直接吃我们的输出**，原因很具体：

- 它的输入是 `linalg` on `memref`，`snaxc` 的 pass 是为 GEMM/卷积加速器写的；
- LIF 的时间演化是**循环携带依赖**（`v` 跨步保持），表达成 `scf.for` + `memref` 可以，
  但要变成 `linalg` 需要先打破这个依赖——那不是 lowering，那是重写算法；
- 它需要 clang、`mlir-opt`、RISC-V 工具链和一个几 GB 的容器才能构建模型。

所以"直接接入"这一步今天走不通。走不通的地方，正确的动作不是硬接，而是**把接口做对**：

- 我们发出去的 MLIR **只用 `builtin / func / memref / arith / scf`，不注册自定义 dialect**。
  这意味着 `mlir-opt` 能读，xdsl 能读，`snaxc` 至少不会因为方言不认识而在第一行退出。
- 我们把 `conv` / `pool` / 残差合并**明确拒绝**（报错而不是近似），因为这几样恰恰是需要
  `linalg` 索引映射的部分——那正是下游比我们做得好的地方，我们不该抢。
- 我们提供的是**golden 向量**：`%s_<layer>` 是 `[T * units]` 的 0/1 轨迹，逐位置可比。
  谁把这份 MLIR 编进 verilator 模型跑通，就能拿它和 PyTorch 的轨迹对齐——这不需要我们
  构建 RTL，也不需要对方信任我们的解释器。

一句话：**verilator 模型不是我们的目标后端，是我们的第三个裁判席**。前两个裁判是
PyTorch 和 nirtorch/snnTorch，都在软件层；它是唯一能判"软件对、RTL 错"的那一个。

### 7.4 四条接入路径，按性价比

| 路径 | 做什么 | 成本 | 收益 | 状态 |
|---|---|---|---|---|
| **A. 读 PyTorch** | `torch.export`/FX → 我们的 IR，`snndsl deploy model.py` | 中（算子匹配 + 三家 LIF 模块识别） | **最高**：把"学我的语法"换成"对现有模型跑一条命令" | 未做 |
| **B. 读 NIR** | `.nir` 当输入，不只当输出 | 低（`nir.read` + 逆向映射） | 让我们能检查 Lava/Norse/snnTorch 产出的图，从自家检查器变成第三方检查器 | 未做 |
| **C. 发 MLIR** | 输出 `builtin/func/memref/arith/scf` 文本 | 低（纯文本，不 build LLVM） | 借 MLIR 生态的后端；`.snn → MLIR → 裸机` 这条路不用自己修 | **已做**，见 §7.5 |
| **D. 上游规范化** | 把 tau 离散化 / 每步脉冲数 / reset 形式写成 NIR 提案，测试向量当 conformance suite | 中（主要是写与推） | 痛点从"我们的差异"变成"标准的缺口"，我们成为参考实现 | 未做 |

A 和 B 的区别值得说清：A 是拿用户，B 是拿同行。两个都要，A 先做——没有人会为了用检查器
而重写模型，这一点 SNN-MLIR 的 `snn-mlir check model.nir` 已经验证过了：他们的入口是零成本的。

### 7.5 已经落地的：`snndsl build` 现在产出 `.mlir`

```
$ snndsl build examples/mnist_mlp.snn -o build/
artifacts:
  module     build/mnist_mlp.py
  ir         build/mnist_mlp.ir.json
  nir        build/mnist_mlp.nir
  mlir       build/mnist_mlp.mlir
```

生成的是什么：一个 `func.func`，参数是扁平 `memref`（输入、每层膜电位、每层脉冲轨迹、
每层权重与偏置），一个 `scf.for` 走 T 步，里面按拓扑序跑各层；dense 是嵌套 `scf.for` 的
顺序累加，LIF 是 `mulf → addf → cmpf → select` 四条 `arith`。没有 tiling，没有向量化，
没有 buffer 复用——**优化是下游的事**。

三条验证，三个裁判，都不在本仓库：

| 命题 | 裁判 | 结果 |
|---|---|---|
| 文件能被 MLIR 生态读 | xdsl 0.74（SNAX 就构建在它上面） | 4 个示例全部解析通过，含 `scf.for` 嵌套与 `iter_args` |
| 文件算的是同一个网络 | PyTorch + xdsl 解释器 | 逐位置比脉冲轨迹，`differ = 0` |
| 文件能被通用 pass 接手 | `xdsl-opt` 三步 pass | `canonicalize` / `convert-scf-to-cf` / `convert-memref-to-ptr` 全部通过，详见 §7.6 |

`tests/test_mlir_export.py` 里还钉了一条容易写错的结构性质：**只能有一个时间循环**。
逐层各开一个 `scf.for` 是自上而下写 lowering 的自然结果，也是错的——第二层会读到第一层
在 T 步里累积的脉冲，而不是第 t 步的脉冲。写这个后端时我先写成了那样，是测试把它挡住的。

明确不做的：`conv`、`pool`、`add`（残差合并）。它们会 raise，消息里写清原因。
一个能解析但算错的文件，是这个项目存在的理由的反面。

### 7.6 接进去有多深：三层，第三层是陷阱

"接入 MLIR 生态"这句话里藏着三种完全不同的事，成本差一个数量级，价值差一个方向。

| 层 | 做什么 | 我们得到什么 | 状态 |
|---|---|---|---|
| **L0 消费者** | 把 `.mlir` / `.nir` 当输入读进来，在自己的检查器里分析 | 检查对象从"自家 4 个示例"变成"任何进了 MLIR 的 SNN" | 未做，路径 B |
| **L1 生产者** | 发只含标准方言的 `.mlir`，不注册方言、不要求插件 | 下游后端白拿；通用 pass 能接管，不用为我们改代码 | **已做**，本节给出证据 |
| **L2 方言成员** | 注册一个 `snn` dialect，别人 `require` 我们的插件才能读 | 看起来最"正统"，实际上把项目变成它批评的东西 | **不做**，理由见下 |

**L1 的完成度用 pass 量，不用文件数。** 一个文件能被解析，只说明语法合法；能被执行，
说明语义闭合。这两种检验都在"读"的层面。生态还有第三种检验，而且是最硬的那种：
**通用 lowering pass 不认识我们，但能不能接手我们的输出。** pass 只匹配 op 的 trait 和
类型，不知道谁写的 IR，所以它跑通等于说"这程序由普通零件拼成"，而不是"一串以 `module {`
开头的文本"。

`tests/test_mlir_ecosystem.py` 用 `xdsl-opt` 命令行（不是 import 同一个库，那是一次意见
数两遍）跑三步，全部通过：

| pass | 断言 | 它排除了什么 |
|---|---|---|
| `canonicalize` | exit 0 | trait 写错、verifier 靠宽容放过 |
| `convert-scf-to-cf` | `scf.for` 归零、`cf.br` 出现、归约累加子变成 block argument | 时间循环用了 lowering 不认识的形式 |
| `convert-memref-to-ptr` | 循环体内 `memref.load/store` **归零**，`ptr_xdsl.ptradd` 出现 | 任何"只有本项目这么写"的访问模式 |

第三步是最有信息量的：`memref<200704xf32>` 加权重的双重下标，被通用的
`o * n_in + i` → `ptradd` 规则吃掉了，我们没为它写过一行适配。**能降，是因为本来就没
发明什么。**

反过来，`convert-memref-to-ptr` 之后**故意留着**的两样东西也值得看：`memref.alloc` 和
memref 类型的函数参数。那是边界。边界用什么表示——栈、DMA buffer、加速器 scratchpad——
是下游编译器的决定，不是我们的。一个已经替下游决定好的文件，只会更难重定向。测试因此
断言了"边界还在"，而不是"memref 全消"。

**L2 为什么是陷阱。** 第一反应通常是"写个 `snn` dialect 才算真接入"。反过来了。MLIR
方言的契约是**每个 op 的语义必须无歧义**，verifier 会替你把这个要求钉死。而本项目存在的
全部理由是：源码里的语义**恰恰有歧义**——`temporal: reset = zero` 但 body 写
`v = v - s*v_th`；tau 的离散化有四五种写法；`AvgPool2d` 被映射成窗口求和。要把这些做成
方言，你得先在方言内部选定一种语义，于是你又成了一个"第 N 个实现"，也就是我们一直在
批评的那类东西，只是这次带着 verifier 的背书。

所以正确的接入姿势不是"让别人 require 我们"，而是"我们去读别人的输入"（L0）。L1 已经
完成了分发通道；L0 才是让检查能力变成可复用的那一步，也是 §7.4 里路径 B 的全部理由。

### 7.7 窗口在哪

如果 SNN-MLIR 补上 PyTorch 前端和 fan-out，我们剩下的只有一件事：**在源码层说
"这个网络上不了硬件"，而且给出证据**。

- `temporal: reset = zero` 但 neuron body 写的是 `v = v - s*v_th`——这种矛盾进 NIR 时
  已经消失了，NIR 只记录最终那个 reset。他们拿到的 `.nir` 永远自洽，连"这里曾经矛盾过"
  都不知道。
- `tau` 的离散化方式不同导致 1.19%–16.5% 的脉冲位置错位——这类数字只有**两家实现同时在手**
  才拿得到，而他们的参考输出来自同一条链。
- `AvgPool2d` 被 nirtorch 映射成 `LPPool2d(norm_type=1)`，也就是窗口求和——能加载、能跑、
  数字错 4 倍。这是差分测试的产物，不是编译器能推出来的。

这三条的共同点是：**都发生在 NIR 之前或 NIR 之外**。这不是他们做得不够好，是他们的输入
已经是被洗过的数据。

窗口不是一个时长，是一个选择：**他们愿不愿意为了这件事，放弃"从 NIR 起步"这个设计。**
在那之前，`.snn` 的价值不在"另一种写法"，在于它是唯一能在训练开始前提出这些问题的地方。
