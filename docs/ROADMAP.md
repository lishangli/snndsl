# 落地路线图

> 这份文档回答一个问题：**从现在这个原型，到有人真正用它做出东西，中间需要发生什么。**
> 每个阶段都写清验收标准，以及"什么信号出现说明我们错了"。

## 0. 现在在哪

| 维度 | 状态 | 证据 |
|---|---|---|
| 编译器全链路 | 可用 | 前端 → IR → 5 个 pass → PyTorch 源码 / NIR |
| 训练闭环 | 可用 | MNIST 97.21%，全量 10000 张 |
| 硬件导出 | **能导出，能读回，未上真机** | NIR 文件可被 `nir.read` 解析，图结构完整 |
| 部署等价验证 | 刚打通 | zero reset 下 PyTorch 与 NIR 参考仿真**逐位一致**（误差 0.0） |
| 用户 | **零** | 没有外部用户，没有访谈 |
| 团队 | 一人 | — |

按技术成熟度算，这是 **TRL 4**：实验室环境下验证了核心原理。
到 TRL 6（相关环境下演示原型）之间，隔着的不是代码量，是**外部接触**。

所以下面三个阶段，前两个的重点都不是写代码。

## P0 · 让"能上硬件"从主张变成证据（0–6 周）

### 为什么先做这个

现在最有说服力的一句话是"zero reset 下逐位一致"，但它有一个前提：
**NIR 参考解释器是我自己写的**。用自己的解释器证明自己的导出正确，
逻辑上是可以自洽的（解释器按规范实现、逐层对比过），但对一个外部工程师来说，
这仍然是"你们自己说自己对"。

必须有一份不依赖我们代码的证据。

### 交付物

| # | 交付物 | 验收标准 |
|---|---|---|
| P0-1 | **第三方仿真器交叉验证** ✅ **已完成** | 同一份 `.nir` 在至少一个**非本项目**的运行时里跑出相同脉冲序列（相对误差 < 1e-5）。候选：`nir` 生态内的 PyTorch/CUDA 后端、snnTorch 读 NIR、或 Nengo 的 NIR 前端 |
| P0-2 | **12 场用户访谈** | 覆盖 3 类角色（硬件厂商工程师、边缘 AI 产品负责人、SNN 研究者）各 4 人。产出：一份"用户实际怎么描述痛点"的原始记录 |
| P0-3 | **`snndsl deploy --report`** ✅ **已完成** | 生成单文件 HTML：可部署性、逐层等价性、成本估算、修改建议。能直接发给一个没见过本项目的人看懂 |
| P0-4 | **三个真实网络的部署检查** ✅ **已完成（做了五个）** | 除 MNIST 外，再覆盖一个卷积网（CIFAR）、一个深层网（残差）、一个非 LIF 神经元（ALIF）。每个都给出"能否部署 + 为什么" |

> **P0-1 结果**（详见 [`P0_CROSS_VALIDATION.md`](P0_CROSS_VALIDATION.md)）：
> `nir` 1.0.8 读文件 + `nirtorch` 2.6 执行图 + `snnTorch` 1.0 执行神经元，
> 1024 张真实 MNIST 上预测一致率 **100%**，`max |output diff| = 0.0`。
> 顺带抓出 4 个本项目 bug（含"验证的不是交付的文件"这一类）与 2 个上游 bug。
>
> **P0-3 / P0-4 结果**（详见 [`P0_DEPLOY_MATRIX.md`](P0_DEPLOY_MATRIX.md)）：
> 五个网络、四种不同结论——全连接 zero reset `PRESERVED`（`max|Δ|=0.0`）；
> subtract reset 实测 top-1 一致率 **99.17%**（精度 95.70%→95.61%，会走样但没崩）；
> ALIF 精度 94.53%→**35.40%**（**已从 WARN 升为 BLOCK**，因为导成积分器是换模型
> 不是近似）；残差网无 merge 原语；卷积网受 NIR 一维神经元限制。
>
> **P0 期间新发现的上游问题**：`nir` 1.0.x 补丁版本之间文件不兼容（1.0.8 写的
> 文件 1.0.4 读不了，而厂商都钉 1.0.4）；`rockpool` 3.1 的 NIR 前端仍在读
> `tau_mem`，任何 nir 1.0 模型都进不去 Xylo 路径。前者我们已用"零 `v_reset`
> 不写字段"绕开，后者见 [`UPSTREAM_ISSUES.md`](UPSTREAM_ISSUES.md)。
>
> **一处更正**：早前版本的这条路线上写着 "subtract 78.1% / ALIF 9.4%"——那两个
> 数字是**没加载权重**（随机初始化）测出来的，不携带信息。现已用训练好的检查点
> 全部重测。
>
> **仍缺**：12 场用户访谈。工具包已备好（[`INTERVIEW_KIT.md`](INTERVIEW_KIT.md)），
> 但访谈不能代做——这一项不完成，P0 不算真收口。

### 验收门槛

- P0-1 通过 → "导出的 NIR 语义正确"这条从**自证**变成**他证**，可以直接写进任何材料
  **→ 已通过：1024 样本 100% 一致、输出差 0.0**
- P0-1 失败 → 说明我们的 NIR 语义理解有偏差，**优先级高于一切**，立即修正
- P0-2 完成后，如果 12 人里没有 4 人以上把"部署一致性"列为前三大痛点 → **重新评估方向**

> **P0-1 的副作用比结论更有价值**：它把一个我们本来会讲过头的说法按住了。
> "支持导出 NIR"对全连接网成立，对卷积网不成立——标准层面不成立，不是我们没做完。
> 现在 `deploy` 会直接报 `BLOCK` 并给出原因，而不是产出一个读不回来的文件。
> 产品叙事因此收紧成：**先做全连接 SNN 的无损部署，卷积 SNN 走"向 NIR 提多维神经元扩展"这条路。**

### 这一步的证伪条件

> 如果第三方仿真器跑出来的结果对不上，而且修正后仍然对不上，
> 那说明 NIR 的语义空间不足以表达 SNN 训练的实际需要。
> 这种情况下，"编译层"这个定位就需要重新论证——可能得先做语义扩展提案，而不是做产品。

## P1 · 让第一个外部用户跑通（6–14 周）

### 目标

从"这个东西很聪明"变成"我们团队在用它"。

一个用户，一个真实任务，一条完整链路：**数据 → 训练 → 部署 → 上机（或上仿真器）→ 精度对齐**。

### 为什么选 SynSense 生态作为第一个目标

| 候选 | 优势 | 障碍 |
|---|---|---|
| **SynSense（Xylo / Speck）** | Rockpool 与 Sinabs 开源且活跃（2026-02 仍在提交）、NIR 支持齐、芯片可买 | AGPL 许可需注意、Xylo 模型容量小 |
| BrainChip（Akida） | 已量产出货（2026-06） | 工具链闭源，MetaTF 需注册 |
| Intel Loihi | 学术影响力最大 | Lava 已归档，下一代 SDK 未发布，**现在不能作为目标** |
| SpiNNaker2 | 规模大、开源彻底 | 面向神经科学，非 ML 部署场景 |

Intel 这条线要**主动放弃一段时间**：Lava 归档、新 SDK 未出，任何投入都可能打水漂。
等新 SDK 公布后再评估——那时如果它真"基于开放标准框架"，我们的 NIR 路线会直接受益。

**P1 阶段已经提前拿到的成果**：厂商工具链读不了 nir 1.0，这件事我们没有停在
"报一个 upstream issue"，而是绕到厂商的**神经元模块**上把语义对照做完，
得到三条可测量的规范缺口（tau 的离散化、每步脉冲数、reset 形式）。
这让项目的定位从"又一个能导 NIR 的前端"变成"能说清同一份文件在不同目标上
到底变成什么"——后者目前没人做。

### 交付物

| # | 交付物 | 验收标准 |
|---|---|---|
| P1-1 | 一个 event-camera 任务的端到端 demo | DVS 手势或 N-MNIST，训练精度 → 部署精度差 < 1pp |
| P1-2 | 一个外部用户的实际使用 | 至少 1 个非本项目的人，按文档独立跑通，全程不需要我们介入 |
| P1-3a | **厂商神经元层面的语义对照** ✅ **已完成** | 绕开读不了 nir 1.0 的 rockpool 前端，用它的 `LIFNeuronTorch` 重建同一张图。对齐 `tau` 换算后，非饱和区逐脉冲 0 处不同；差异被拆成三条规范缺口并各自量化（[`SEMANTICS.md`](SEMANTICS.md)） |
| P1-3 | 首次真机或厂商仿真器验证 | 在 Xylo 仿真器（Rockpool 提供）或真机上，脉冲输出与 NIR 参考仿真一致 |
| P1-4 | 循环突触支持 | `dense g <- h, g` 能编译、能训练、能导出。这是当前最大的功能空白 |
| P1-5 | 文档 | 一个工程师能在 30 分钟内从零跑到 demo，不需要读源码 |

### 验收门槛

- P1-3a 已完成 → 但它证明的是"软件语义可以对齐"，**不是"芯片上会一致"**。
  硅片上还有权重位宽、膜电位定点化，P1-3 才算真机证据
- P1-3 通过 → 这是整个项目**最硬的一块证据**，可以直接对硬件厂商谈合作
- P1-2 失败（用户仍需介入）→ 文档和易用性问题优先于新功能
- P1-4 若与 P1-3 冲突（时间不够），**先做 P1-3**。功能少一个不致命，真机没验证致命

## P2 · 生态占位（3–6 月）

到了这一步才有资格谈"标准"。核心不是功能，是**让别人愿意用你的写法**。

| # | 动作 | 成功信号 |
|---|---|---|
| P2-1 | 开源发布 + 一篇技术报告 | 6 个月内 300+ stars、10+ 外部 issue（说明真有人在用） |
| P2-2 | 争取 `.snn` 进入论文附录 | 至少 2 篇非本团队论文用 `.snn` 描述网络 |
| P2-3 | 与一家硬件厂商的官方文档互链 | 他们的 getting-started 提到我们的工具 |
| P2-4 | 注册一个 NIR 前端实现 | 在 `neuroir.org` 的实现列表里出现 |
| P2-5 | 性能：编译 10 层网络 < 2s | 现在是毫秒级，但要保证规模上去后不退化 |

### 商业化的触发条件

不要在 P2 之前谈收入。但要知道什么信号出现才该开始谈：

- 有 3 家以上公司在 issue 里问"有没有企业版 / 能不能私有部署"
- 有硬件厂商主动问"能不能做我们的官方前端"
- 有团队在 production 场景里用（哪怕免费）

三个里出现任意两个，才开始做商业版。提前做会把精力从生态挪到销售，而这时候还没有生态。

## 不做清单

明确不做什么，比明确做什么更能说明这个项目想清楚了。

| 不做 | 原因 |
|---|---|
| **不造芯片** | 我们站在所有硬件厂商一边。造芯片就变成了和客户竞争 |
| **不做神经科学仿真** | Brian2（1,248★）、NEST（673★）已经很成熟，且用户群不重叠 |
| **不做通用深度学习编译器** | TVM / XLA / torch.compile 的战场，我们只做 SNN 特有的事（时间语义、脉冲稀疏性） |
| **短期不支持 Intel Loihi** | Lava 已归档，新 SDK 未发布。等，不追 |
| **不做闭源核心** | 编译器的价值来自网络效应，闭源起不来。商业版卖的是支持和集成，不是功能阉割 |
| **不做云平台** | 在有人用之前，云平台是纯成本中心 |

## 关键假设，以及它们怎么被证伪

一个诚实的计划必须写明：**如果什么发生，我就承认方向错了。**

| 假设 | 如果错了会看到什么 | 应对 |
|---|---|---|
| 训练与部署的一致性是真实痛点 | 12 场访谈里 < 4 人提及 | 转向"成本估算"作为主卖点（痛点 #2 同样已验证） |
| NIR 会继续作为硬件通用标准 | 某个大厂推出竞争标准并获多家采用 | NIR 导出层做薄，加一层适配，成本可控 |
| 硬件厂商愿意接入第三方前端 | 接触 5 家，0 家愿意提供硬件细节 | 转向纯软件价值：训练 + 成本估算 + GPU 上的稀疏推理 |
| SNN 本身会在边缘场景落地 |  neuromorphic 芯片年出货量持续 < 10 万片 | 这个风险不由我们承担，但要知道自己在一条小船上 |

最后一条要说清楚：**我们赌的不是 SNN 一定赢，而是"如果 SNN 赢，编译层是必经之路"。**
这个赌注的下行是有界的（硬件不赢，我们还可以服务 GPU 上的稀疏推理），
上行是开放的（硬件赢了，我们是所有硬件的入口）。

## 资源需求

按 P0–P1 算，最小可行团队：

| 角色 | 投入 | 为什么必需 |
|---|---|---|
| 编译器/系统 | 1 全时 | 核心，不可外包 |
| 用户接触 | 0.5 全时 | **当前最大的缺口**。没有这个，P0-2 和 P1-2 都做不了 |
| 硬件对接 | 按需 | P1-3 阶段需要，可以顾问形式 |

最缺的不是工程能力，是**能持续和外部用户对话的人**。
一个人写代码可以写出原型，但写不出产品——产品的定义来自用户，不来自代码。
